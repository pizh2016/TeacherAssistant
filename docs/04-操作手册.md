# 04 - 打包部署操作手册

> 本文档覆盖从零开始的环境初始化、日常开发启动、产品构建发布、部署验证全流程。
> 后端采用 pythonenv + .pyc 编译方案构建产品运行时。

---

## 一、技术方案概览

| 维度 | 方案 |
|------|------|
| **后端打包** | 便携 Python ZIP 解压 + pip 安装依赖 + .pyc 编译 |
| **运行时** | `runtime/pythonenv/` 独立目录，持久存在 |
| **启动方式** | 直接运行 `pythonenv/python.exe`，启动速度快 |
| **调试能力** | 好（可直接修改 .py 文件调试） |
| **更新策略** | 可独立更新 pythonenv/ 或业务代码 |
| **配置管理** | `defaults/settings.json` + `data/settings.json`（JSON 嵌套结构） |
| **老师端 H5** | `teacher-app/`（独立 Vite + Vue 项目） |
| **大屏端** | `display-app/`（纯客户端，Electron 壳 / 纯 Web） |
| **构建脚本** | `build_runtime.py` + 4 个 `_build_*.py` 模块（模块化） |
| **源码保护** | .pyc 编译 + .py 剥离（基本保护） |

## 五、阶段三：产品构建

> 模块化构建流程，支持智能跳过、增量依赖安装、.pyc 源码保护。

### 5.1 后端构建（pythonenv + .pyc）

```powershell
cd backend

# 基础构建（智能跳过已有环境）
python scripts/build_runtime.py

# 强制全量重建
python scripts/build_runtime.py --force

# 构建 + 可选 .pyc 深度编译（剥离 .py 源码）
python scripts/build_runtime.py --phase2

# 构建 + 打包为 ZIP 发布包
python scripts/build_runtime.py --package

# 完整构建（强制 + 深度编译 + 打包）
python scripts/build_runtime.py --force --phase2 --package
```

**构建流程：**
```
Phase 1: Build clean runtime/pythonenv/
  ├── 解压 Python ZIP → runtime/pythonenv/
  ├── ensurepip 引导 pip
  ├── 安装 requirements-*.txt 依赖
  └── 清理（tkinter, __pycache__, .dist-info, Scripts/）

Phase 2: Recompile project source (src/horn/ → pythonenv)
  ├── 用 .venv 构建 wheel
  ├── 安装 wheel 到 pythonenv
  ├── 编译 .py → .pyc (legacy)
  └── 剥离 .py 源码（保留无 .pyc 的文件）

Phase 3 (optional): Compile .py → .pyc and slim
  ├── 编译 site-packages/ 全部 .py → .pyc
  ├── 编译 Lib/ stdlib .py → .pyc
  └── 智能剥离 .py（仅删除有 .pyc 对应的文件）

Package: ZIP release
  ├── 复制 runtime/pythonenv/
  ├── 复制 defaults/
  ├── 复制 teacher-app/dist/
  ├── 生成 start-backend.bat
  ├── 生成 version.json + README.txt
  └── 创建 ZIP + SHA256
```

**产物位置：**
```
backend/generated/release/Classroom-Horn-v0.2.0-win-x64.zip
```

### 5.2 教师端 H5 构建

教师端 H5 作为静态文件由后端托管，构建产物会被后端打包流程自动引用。

```powershell

# 构建生产版本（TypeScript 类型检查 + Vite 打包）
```

## 七、配置管理方案说明

### 7.1 配置加载顺序（后者覆盖前者）

1. `defaults/settings.json` — 出厂默认（只读，随产品发布）
2. `data/settings.json` — 用户覆盖（首次启动创建，持久化）
3. 环境变量 — 最高优先级（如 `JWT_SECRET_KEY`）

### 7.2 settings.json 结构

```json
{
  "version": 1,
  "app": {
    "name": "Classroom Horn",
    "version": "0.2.0",
    "debug": true
  },
  "database": {
    "url": "sqlite:///./data/classroom_horn.db"
  },
  "auth": {
    "jwt_algorithm": "HS256",
    "access_token_expire_minutes": 30
  },
  "ws": {
    "heartbeat_interval": 30,
    "max_reconnect_attempts": 5,
    "join_timeout": 10
  },
  "cors": {
    "origins": "*"
  }
}
```

### 7.3 环境变量映射

| 环境变量 | JSON 路径 | 类型 |
|---------|-----------|------|
| `APP_NAME` | `app.name` | string |
| `DEBUG` | `app.debug` | bool |
| `DATABASE_URL` | `database.url` | string |
| `JWT_SECRET_KEY` | `auth.jwt_secret_key` | string |
| `JWT_ALGORITHM` | `auth.jwt_algorithm` | string |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | `auth.access_token_expire_minutes` | int |
| `WS_HEARTBEAT_INTERVAL` | `ws.heartbeat_interval` | int |
| `CORS_ORIGINS` | `cors.origins` | string |

### 7.4 运行时配置修改 API

通过 `config.update_runtime_setting()` 可在线修改白名单配置项并持久化到 `data/settings.json`：

```python
from horn.config import update_runtime_setting

# 修改 WS 心跳间隔
update_runtime_setting("ws.heartbeat_interval", 15)

# 修改 CORS 来源
update_runtime_setting("cors.origins", "http://localhost:5173")
```

## 九、局域网跨网段部署指南

> 本章节针对“办公室电脑 ↔ 教室电脑”跨网段部署场景。

### 9.1 部署拓扑

```
┌─────────────────────────────────────────────────────────────────┐
│                        局域网环境                                │
│                                                                 │
│  ┌─────────────────────────┐       ┌─────────────────────────┐  │
│  │  办公室电脑（服务端）    │       │  教室电脑（客户端）    │  │
│  │  IP: 192.168.5.153      │       │  IP: 192.168.40.27    │  │
│  │  子网: 192.168.5.x/24   │       │  子网: 192.168.40.x/24│  │
│  │                         │       │                         │  │
│  │  ┌───────────────────┐  │       │  ┌───────────────────┐  │  │
│  │  │ 后端服务 :18800   │  │◄─────►│  │ 大屏端 Electron │  │  │
│  │  │ (0.0.0.0)         │  │ 跨网段 │  │ (纯客户端)       │  │  │
│  │  ├───────────────────┤  │ 路由   │  ├───────────────────┤  │  │
│  │  │ 教师端 H5         │  │       │  │                   │  │  │
│  │  │ (静态文件托管)    │  │       │  │                   │  │  │
│  │  └───────────────────┘  │       │  └───────────────────┘  │  │
│  └─────────────────────────┘       └─────────────────────────┘  │
│                                                                 │
│              ▲ 路由器 / 三层交换机                                │
│              │ 192.168.5.1 ↔ 192.168.40.1                      │
└─────────────────────────────────────────────────────────────────┘
```

### 9.2 网络角色分配

| 角色 | 部署位置 | IP 地址 | 运行服务 |
|------|----------|---------|----------|
| **服务端** | 办公室电脑 | `192.168.5.153` | 后端 (port 18800) + 教师端 H5 静态托管 |
| **客户端** | 教室电脑 | `192.168.40.27` | 大屏端 Electron 应用 |

### 9.3 跨网段通信前提条件

由于两端处于不同子网（`192.168.5.x` 与 `192.168.40.x`），需确保：

1. **路由互通**：局域网内存在三层交换机或路由器，能够转发 `192.168.5.0/24` 与 `192.168.40.0/24` 之间的流量
2. **防火墙放行**：
   - 服务端 Windows 防火墙放行 TCP 端口 `18800`（后端 HTTP + WebSocket）
   - 客户端 Windows 防火墙放行出站连接到 `192.168.5.153:18800`
3. **后端监听地址**：后端必须绑定 `0.0.0.0`（已在 `defaults/settings.json` 中配置）

### 9.4 服务端防火墙配置（办公室电脑）

```powershell
# 以管理员身份运行 PowerShell
# 添加入站规则，允许 TCP 18800 端口
New-NetFirewallRule -DisplayName "Classroom Horn Backend" `
  -Direction Inbound -Protocol TCP -LocalPort 18800 -Action Allow

# 验证规则已添加
Get-NetFirewallRule -DisplayName "Classroom Horn Backend"
```

### 9.5 网络连通性验证

在教室电脑（客户端）上执行：

```powershell
# 1. 测试路由可达
ping 192.168.5.153

# 2. 测试后端端口可达
Test-NetConnection -ComputerName 192.168.5.153 -Port 18800

# 3. 测试 HTTP 健康检查
curl http://192.168.5.153:18800/health
# 预期: {"status":"healthy",...}
```

### 9.6 大屏端配置后端地址

大屏端首次启动时配置后端服务器地址：

1. 启动大屏端应用
2. 在配对页面展开「🌐 服务器地址」折叠区
3. 输入 `http://192.168.5.153:18800`
4. 点击「保存」，地址持久化到 `localStorage`
5. 输入 6 位配对码，点击「连接」

> 后续启动自动使用已保存的地址，无需重复配置。
> 如需修改，可在配对页面重新展开「服务器地址」区域修改。

### 9.7 教师端访问方式

教师端 H5 作为静态文件由后端托管，部署后通过浏览器直接访问：

- **部署后访问**：`http://192.168.5.153:18800/static/teacher/index.html`（后端静态托管）
- **开发模式**：`http://localhost:5173`（Vite 开发服务器，自动代理 API 到后端）

> 教师端构建产物（`teacher-app/dist/`）在后端打包时自动复制到发布包的 `teacher-app/` 目录。
> 后端通过 `api.py` 中的 `StaticFiles` 挂载 `/static/teacher` 路径提供服务。

### 9.8 常见问题排查

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 大屏端连接超时 | 路由不通 | 检查路由器/三层交换机配置，确保两子网互通 |
| 大屏端连接被拒绝 | 防火墙拦截 | 检查服务端防火墙入站规则 |
| 大屏端显示“配对码无效” | 后端未启动 | 确认后端服务正在运行 |
| 教师端无法访问 | 端口未开放 | 检查 Vite 开发服务器或后端静态托管配置 |
| WebSocket 连接断开 | 网络不稳定 | 检查网络设备，确认心跳间隔配置 |
