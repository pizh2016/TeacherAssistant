# 喊话小喇叭 - 总体技术方案设计

## 1. 项目概述

### 1.1 项目背景

在传统校园场景中，教师需要频繁往返于办公室与教室之间传达通知、提醒和叮嘱，既浪费时间又影响教学效率。"喊话小喇叭"系统旨在解决这一痛点：让老师用手机发送文字，班级大屏实时语音播报，告别来回奔波，让每一次通知、叮嘱、提醒直达教室。

### 1.2 核心目标

- **实时通知**：老师发送文字后，班级大屏在2秒内显示并可选语音播报
- **零门槛使用**：老师端纯H5无需安装，扫码或输入配对码即可使用
- **强提醒能力**：大屏端Electron应用支持强制置顶，覆盖PPT等全屏应用
- **多班级管理**：支持一位老师管理多个班级，批量发送通知
- **历史追溯**：所有喊话记录云端留存，随时复盘审计
- **私有化部署**：数据加密存储，支持校园内网稳定可靠运行

### 1.3 设计原则

1. **简单可靠优先**：MVP聚焦核心"文字→大屏显示"流程，避免过度设计
2. **现有技术栈最大化**：充分利用Python、Electron、Vite技能，降低学习成本
3. **渐进式扩展**：架构预留图片/视频通知、定时任务等扩展接口
4. **离线可用**：语音合成支持完全离线（Web Speech API + pyttsx3）
5. **安全合规**：JWT认证、消息加密、数据最小化存储

## 2. 竞品分析

### 2.1 主要竞品对比

| 产品名称 | 核心功能 | 技术特点 | 优点 | 缺点 |
|---------|---------|---------|------|------|
| **班小二班级小喇叭** | 语音/文字转语音广播、图片投屏、远程巡课、多班批量广播、定时播报 | 微信小程序+Windows客户端，依赖希沃大屏生态 | 免费使用、微信生态易接入、支持6班批量、可定向学生 | 强依赖希沃硬件、需安装Windows客户端、云端服务不可控 |
| **WorkBuddy班级喊话系统** | 文字跑马灯/弹窗、定时/即时播报、多教室管理、配对码绑定 | Web前端+后端云服务，6位配对码机制，<1秒延迟 | 零代码配置、轻量级、无需安装客户端、跨平台 | 功能相对简单、无语音播报、无历史记录追溯 |
| **班级管理小助手** | 手机远程喊话、定时安全提醒、作业登记、积分管理 | 移动端APP+Web后台，支持语音录制重发 | 功能丰富、有定时自动化、数据同步 | APP需安装、界面较复杂、学习成本高 |

| **企业微信家长通知** | 家校通讯录、作业通知、已读状态查看 | 企业微信生态，API开放 | 与企业微信打通、API可扩展 | 同样非实时大屏展示、依赖企业微信环境 |
| **传统IP网络广播** | 全校/分区广播、定时播放、紧急广播 | 专用硬件设备+IP网络协议，SXB-666服务器 | 稳定性高、覆盖范围广、音质好 | 成本高昂、部署复杂、无法个性化定向、操作繁琐 |

### 2.2 关键洞察

**可借鉴的设计模式：**
1. **配对码机制**（WorkBuddy）：6位数字配对码，降低配置复杂度，避免账号体系
2. **三种展示样式**（班小二）：跑马灯、全屏弹窗、侧边弹窗，适配不同场景
3. **批量广播**：支持1-6个班级同时接收，适合带多班的老师
4. **定时播报**：放学前安全提示等固定内容可预设周期性重复
5. **历史留存**：所有广播记录可回看复盘，满足学校管理需求

**需规避的问题：**
1. **硬件依赖过重**：班小二强依赖希沃大屏，限制了适用范围
2. **客户端安装门槛**：Windows客户端需IT人员维护，增加部署成本
3. **过度功能堆砌**：巡课、文件传输、积分管理等偏离核心"喊话"场景
4. **网络不稳定容错不足**：多数产品未明确说明断线重连机制

### 3.2 核心用户流程

```
老师操作流程：
打开浏览器 → 访问老师端 H5 → 扫码/输入配对码 →
选择目标班级 → 输入通知文字（最多500字）→ 选择展示方式（弹窗/跑马灯）→
可选：开启语音播报 → 点击发送 → 收到发送成功反馈

大屏端流程：
启动Electron应用 → 输入6位配对码 → 建立WebSocket连接 →
进入待机状态（透明背景）→ 收到WebSocket消息 → 自动全屏 →
按设定方式展示 + 语音播报 → 倒计时结束/手动关闭 →
退出全屏返回待机
```

**端到端延迟目标：<2秒**（从点击发送到屏幕显示）

### 4.2 技术选型对比

#### 4.2.1 老师端：H5 vs Electron

| 维度 | H5（推荐） | Electron |
|------|-----------|----------|
| **安装门槛** | ⭐⭐⭐⭐⭐ 零安装，浏览器访问 | ⭐⭐ 需下载安装包(~100MB) |
| **跨平台** | ⭐⭐⭐⭐⭐ 手机/平板/电脑通用 | ⭐⭐⭐ 仅桌面端 |
| **更新迭代** | ⭐⭐⭐⭐⭐ 服务端即更新 | ⭐⭐ 需重新打包分发 |
| **系统级能力** | ⭐⭐ 无全局快捷键/托盘 | ⭐⭐⭐⭐⭐ 完整系统API |
| **开发成本** | ⭐⭐⭐⭐⭐ 纯前端，复用组件 | ⭐⭐⭐ 需Electron主进程 |
| **最终选择** | ✅ **H5** | ❌ 超配 |

**选择理由：** 老师主要在办公室固定位置使用，手机/平板/电脑浏览器均可访问；零安装优势远大于失去的系统级能力；后续如需全局快捷键可作为P2增强。

#### 4.2.2 大屏端：Electron 纯客户端壳

| 能力 | Web浏览器 | Electron |
|------|----------|----------|
| **强制置顶** | ⭐ Fullscreen API受限 | ⭐⭐⭐⭐⭐ setAlwaysOnTop('screen-saver') |
| **开机自启** |  不支持 | ⭐⭐⭐⭐⭐ 注册表/启动文件夹 |
| **隐藏任务栏** | ❌ 浏览器始终可见 | ⭐⭐⭐⭐⭐ skipTaskbar: true |
| **阻止屏保** | ❌ 需用户交互 | ⭐⭐⭐⭐⭐ powerSaveBlocker |
| **离线稳定性** | ⭐⭐ 缓存可能被清理 | ⭐⭐⭐⭐⭐ 本地文件确定性强 |
| **最终选择** | ✅ **纯 Web（兼容部署）** | ✅ **Electron（桌面增强）** |

**选择理由：** 大屏端的核心价值是"强制置顶覆盖PPT"，这是浏览器Fullscreen API无法实现的；Electron提供系统级控制能力。同时大屏端也支持纯 Web 部署（通过 Nginx 反代），后端地址通过 `localStorage` 用户配置或同源请求获取，无需内嵌任何后端进程。

#### 4.2.3 后端：Python FastAPI的理由

| 维度 | Python FastAPI | Node.js Express | Go Gin |
|------|---------------|----------------|--------|
| **开发效率** | ⭐⭐⭐⭐⭐ 最熟悉语言 | ⭐⭐⭐ 需学习新生态 | ⭐⭐ 需专门技能 |
| **WebSocket支持** | ⭐⭐⭐⭐ starlette原生 | ⭐⭐⭐⭐⭐ socket.io封装好 | ⭐⭐⭐⭐⭐ 原生支持 |
| **异步性能** | ⭐⭐⭐⭐ asyncio | ⭐⭐⭐⭐⭐ 事件循环 | ⭐⭐⭐⭐⭐ goroutine |
| **SQLite集成** | ⭐⭐⭐⭐⭐ 内置sqlite3 | ⭐⭐⭐ better-sqlite3 | ⭐⭐⭐ go-sqlite3 |
| **TTS生态** | ⭐⭐⭐⭐⭐ pyttsx3成熟 | ⭐⭐ 库较少 | ⭐ CGO调用 |
| **定时任务** | ⭐⭐⭐⭐⭐ APScheduler | ⭐⭐⭐ node-cron | ⭐⭐ robfig/cron |
| **最终选择** | ✅ **Python** | ❌ | ❌ |

**选择理由：** 本项目I/O密集型而非计算密集型，Python异步性能足够；pyttsx3、APScheduler等库成熟度高。

#### 4.2.4 实时通信：WebSocket vs SSE

| 维度 | WebSocket（推荐） | SSE | 长轮询 |
|------|-----------------|-----|--------|
| **双向通信** | ✅ 支持 |  单向 | ❌ 单向 |
| **自动重连** | ❌ 需手动实现 | ✅ 原生支持 | ❌ 需手动实现 |
| **穿透代理** | ⭐⭐ 需ws/wss支持 | ⭐⭐⭐⭐ HTTP天然支持 | ⭐⭐⭐⭐⭐ HTTP支持 |
| **实现复杂度** | ⭐⭐⭐ FastAPI原生API | ⭐⭐⭐⭐⭐ StreamingResponse | ⭐⭐ 复杂 |
| **延迟** | ⭐⭐⭐⭐⭐ <100ms | ⭐⭐⭐⭐ <200ms | ⭐⭐ >500ms |
| **最终选择** | ✅ **WebSocket** | 备选 | ❌ |

**选择理由：** 虽然当前是单向推送，但预留大屏端上报"已显示"状态的能力；FastAPI的WebSocket API足够简洁。

#### 4.2.5 数据库：SQLite

| 维度 | SQLite（MVP推荐） | PostgreSQL | MySQL |
|------|-----------------|-----------|-------|
| **部署复杂度** | ⭐⭐⭐⭐⭐ 零配置，单文件 | ⭐⭐ 需独立服务 | ⭐ 需独立服务 |
| **并发写入** | ⭐⭐ 低（写锁） | ⭐⭐⭐⭐⭐ 高 | ⭐⭐⭐⭐ 高 |
| **私有化部署** | ⭐⭐⭐⭐⭐ 拷贝即可 | ⭐⭐ 需运维 | ⭐⭐ 需运维 |
| **扩展性** | ⭐⭐ 难横向扩展 | ⭐⭐⭐⭐⭐ 主从复制 | ⭐⭐⭐⭐ 主从复制 |
| **最终选择** | ✅ **SQLite（MVP）** | 生产升级 | 备选 |

**选择理由：** MVP阶段数据量小（假设100个班级×每天50条消息×30天=15万条），SQLite完全胜任；私有化部署时客户无需安装数据库软件；后期可通过SQLAlchemy无缝迁移PostgreSQL。

#### 4.2.6 语音合成：混合方案

| 维度 | Web Speech API | pyttsx3 | 阿里云TTS |
|------|---------------|---------|----------|
| **成本** | ⭐⭐⭐⭐ 免费 | ⭐⭐⭐⭐⭐ 免费 | ⭐⭐ 按字符收费 |
| **离线能力** | ⭐⭐⭐⭐⭐ 完全离线 | ⭐⭐⭐⭐⭐ 完全离线 | ❌ 需联网 |
| **音色质量** | ⭐⭐⭐ 机械感较强 | ⭐⭐⭐⭐ 系统TTS引擎 | ⭐⭐⭐⭐⭐ 自然流畅 |
| **延迟** | ⭐⭐⭐⭐⭐ 本地即时 | ⭐⭐⭐⭐ 本地生成 | ⭐⭐⭐ 网络延迟 |
| **私有化部署** | ⭐⭐⭐⭐⭐ 无依赖 | ⭐⭐⭐⭐⭐ 无依赖 | ❌ 依赖云服务 |
| **最终选择** | ✅ **MVP用Web Speech** | ✅ **增强用pyttsx3** | ❌ |

**选择理由：** MVP阶段用Web Speech API零后端依赖，快速上线；增强阶段用pyttsx3后端统一生成音频，音质一致性更好；两者都完全离线，符合私有化部署要求。

### 4.3 关键技术决策说明

1. **为何老师端选H5而非Electron？**
   - 老师使用场景分散（办公室/家中/路上），手机/平板/电脑都需要访问
   - 零安装优势远大于失去的系统级能力（全局快捷键非核心需求）
   - H5更新即时生效，无需重新打包分发

2. **为何大屏端必须用Electron？**
   - 核心价值是"强制置顶覆盖PPT"，浏览器Fullscreen API无法实现
   - `setAlwaysOnTop(true, 'screen-saver')` 是系统级API，只有Electron能调用
   - 开机自启、隐藏任务栏、阻止屏保等能力都是系统级的

3. **为何后端选Python而非Node.js？**
   - Python 开发效率最高
   - pyttsx3、APScheduler等库在Python生态中更成熟
   - FastAPI的WebSocket API足够简洁，无需socket.io

4. **为何MVP用SQLite而非PostgreSQL？**
   - 私有化部署零运维，客户只需运行一个程序
   - 初期数据量小，SQLite完全胜任
   - SQLAlchemy支持无缝迁移，后期可切换

### 5.3 WebSocket 连接管理

```python
# backend/src/horn/ws/manager.py
from fastapi import APIRouter, WebSocket, WebSocketDisconnect
from typing import Dict, Set

router = APIRouter()

# 班级频道管理: {class_id: set(websocket_connections)}
class_rooms: Dict[int, Set[WebSocket]] = {}

@router.websocket("/ws/class/{class_id}")
async def websocket_endpoint(websocket: WebSocket, class_id: int):
    await websocket.accept()
    if class_id not in class_rooms:
        class_rooms[class_id] = set()
    class_rooms[class_id].add(websocket)
    try:
        while True:
            data = await websocket.receive_text()
            if data == "heartbeat":
                await websocket.send_text('{"type":"pong"}')
    except WebSocketDisconnect:
        class_rooms[class_id].discard(websocket)
        if not class_rooms[class_id]:
            del class_rooms[class_id]

async def broadcast_to_class(class_id: int, message: dict):
    if class_id in class_rooms:
        disconnected = set()
        for ws in class_rooms[class_id]:
            try:
                await ws.send_json(message)
            except Exception:
                disconnected.add(ws)
        class_rooms[class_id] -= disconnected
```

// display-app/src/composables/useTTS.ts
export function useTTS() {
  function speakText(text: string, lang = 'zh-CN') {
    if (!('speechSynthesis' in window)) return false;
    window.speechSynthesis.cancel();
    const utterance = new SpeechSynthesisUtterance(text);
    utterance.lang = lang;
    utterance.rate = 1.0; utterance.pitch = 1.0; utterance.volume = 1.0;
    const voices = window.speechSynthesis.getVoices();
    const zhVoice = voices.find(v => v.lang.startsWith('zh'));
    if (zhVoice) utterance.voice = zhVoice;
    window.speechSynthesis.speak(utterance);
    return true;
  }
  function stopSpeaking() { window.speechSynthesis.cancel(); }
  return { speakText, stopSpeaking };
}

#### 9.2.2 大屏端 Electron 打包

cd display-app

#### 9.2.3 私有化部署步骤

1. **部署后端**：
   ```bash
   cd C:\ClassroomHorn
   .\start-backend.bat
   ```
2. **部署大屏端**：
   ```bash
   ClassroomHornDisplay-Setup-x64.exe
   # 或
   ClassroomHornDisplay-Portable.exe
   ```
3. **配置大屏端后端地址**：首次启动大屏端时，通过客户端 UI 输入后端服务器 URL（如 `http://192.168.1.100:18800`），地址持久化到 `localStorage`，后续启动自动连接。
4. **配置配对码**：访问 `http://<后端地址>:18800/docs` 创建班级并获取配对码
5. **设置开机自启**：将大屏端快捷方式放入启动文件夹

## 10. 总结

### 10.1 核心技术栈

| 层级 | 技术 | 版本 |
|------|------|------|
| 老师端 | HTML5 + Vue 3 + Vite + TypeScript | 最新稳定版 |
| 大屏端 | Electron（纯客户端壳）/ 纯 Web | Electron 28+ |
| 后端 | Python + FastAPI + uvicorn | Python 3.10.11 |
| 数据库 | SQLite + SQLAlchemy + Alembic | 内置 |
| 实时通信 | WebSocket (starlette) | 内置 |
| 后端配置 | defaults/settings.json + data/settings.json + 环境变量 | 自研 |
| 大屏端后端地址 | localStorage → Vite define → location.origin | 自研 |
| 语音合成 | Web Speech API + pyttsx3 | 浏览器原生 + pip |
| 定时任务 | APScheduler | pip |
| 认证 | JWT (python-jose) | pip |
| 产品打包 | pythonenv + .pyc 编译 | 自研模块化脚本 |
| 前端打包 | electron-builder (NSIS + portable) | npm |

### 10.2 关键成功因素

1. **极致简单的用户体验**：老师3步完成发送，大屏端自动显示无需人工干预
2. **稳定的实时性**：端到端延迟<2秒，断线重连无消息丢失
3. **灵活部署**：后端独立部署在服务器；大屏端 Electron 安装包或纯 Web 均可连接任意后端地址；老师端纯H5零安装
4. **强制置顶能力**：Electron的`setAlwaysOnTop('screen-saver')`确保通知不被忽略
