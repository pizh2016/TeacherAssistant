# 喊话小喇叭 - 项目初始开发方案

> **文档定位**：面向项目开发者的完整方案 —— 目录结构、环境配置、版本控制、打包发布、文档规划。
> **关联文档**：[总体技术方案设计](00-总体技术方案设计.md) | [系统架构图](architecture.png)

> ℹ️ **实现说明**
> 本文档描述当前已落地的最终方案，与代码实现完全一致。关键接口契约以
> [`02-后端API设计与实现.md`](02-后端API设计与实现.md) 为准，完整技术方案以
> [`00-总体技术方案设计.md`](00-总体技术方案设计.md) 为准：
> - **模块命名**：后端包为 `backend/src/horn/`；FastAPI 应用工厂在
>   `api.py`，WebSocket 在 `ws/manager.py`，
>   REST 拆分到 `routes/`（auth/classes/messages）。
> - **`.venv` 位置**：位于 **`backend/.venv`**（不在项目根）。启动命令为 `cd backend`
>   后 `.venv\python.exe -m horn`。`.venv` 为
>   完整便携 Python（无 `Scripts\Activate.ps1`，请勿 activate）。
> - **依赖拆分**：采用 `requirements-core/-db/-auth/-tts/-dev/-build.txt`；
>   `pyproject.toml` 为唯一事实源。
> - **打包方案**：采用 **pythonenv + .pyc 编译**（见 `scripts/build_runtime.py` 及
>   `_build_*.py` 模块化脚本），从便携 Python ZIP 构建独立运行时。
> - **配置管理**：后端使用 **`defaults/settings.json`（出厂默认）+
>   `data/settings.json`（运行时持久化）+ 环境变量覆盖** 三层配置方案（见 `config.py`）。
>   大屏端不再读取本地 `settings.json`，后端地址由 `localStorage` 用户配置、Vite define 或同源请求获取。
> - **大屏端架构**：大屏端为**纯客户端应用**（Electron 桌面壳或纯 Web 部署），后端作为独立服务部署在远程服务器，
>   双方通过 HTTP/WebSocket 通信。大屏端不再包含任何启动、管理本地 Python 后端进程的逻辑。
> - **老师端 H5**：作为 **`teacher-app/`** 独立项目开发
>   （Vue 3 + Vite + TypeScript），开发时通过 Vite proxy 代理 API，构建产物可被后端或 Electron 消费。
> - **Python 版本**：统一 **3.10.11**。
> - **pip.ini**：位于 `backend/pip.ini`，pip **不会**自动读取该路径；由 `setup.ps1` 通过
>   `PIP_CONFIG_FILE` 显式挂载（并同时设置 `PIP_INDEX_URL`/`PIP_TRUSTED_HOST`）。

### 1.2 核心设计原则

| 原则 | 说明 |
|------|------|
| **前后端独立版本号** | `VERSION_BACKEND` + `VERSION_GUI` 分别演进 |
| **pythonenv + .pyc 打包** | 便携 Python ZIP 构建独立运行时，.pyc 编译保护源码 |
| **模块化构建脚本** | `_build_shared.py` / `_build_pythonenv.py` / `_build_compile.py` / `_build_package.py` |
| **双阶段构建** | 阶段一：setup.ps1 初始化开发环境；阶段二：build_runtime.py 产品构建 |
| **智能跳过机制** | pythonenv 有效性检查 + mtime 对比 requirements，仅安装变更的依赖 |
| **大屏端后端地址** | `localStorage` → Vite define → `location.origin` | 自研 |
| **文档编号体系** | `01-`, `02-`, ... 按开发顺序编号 |
| **pip.ini 项目级配置** | 放在 backend/ 根目录，由 setup.ps1 经 PIP_CONFIG_FILE 显式挂载（pip 不会自动读取该路径） |

## 三、离线 Python 环境配置（本地 ZIP + 公网）

### 3.1 环境约束

| 约束 | 说明 |
|------|------|
| **网络环境** | **公网 PyPI**（无离线镜像） |
| **Python 来源** | 本地 ZIP `python-3.10.11-amd64.zip` |
| **Python 版本** | 3.10.11 |
| **pip 配置** | 指向公网 PyPI（默认） |

### 3.2 pip.ini 配置（backend/pip.ini）

```ini
[global]
index-url = https://pypi.org/simple/

[install]
trusted-host = pypi.org
```

> **说明**：本项目不使用离线镜像服务器，直接访问公网 PyPI。若后续需要切换为内网镜像，修改此文件即可。

### 3.3 setup.ps1 适配（本地 ZIP + 公网 pip）

```powershell
# backend/scripts/setup.ps1（简化版）

$ErrorActionPreference = "Stop"
$ProjectRoot = Split-Path -Parent $PSScriptRoot
$VenvPath = Join-Path (Split-Path -Parent $ProjectRoot) ".venv"
$PythonZip = Join-Path (Split-Path -Parent $ProjectRoot) "python-3.10.11-amd64.zip"

Write-Host "=== 喊话小喇叭 - 开发环境初始化 ===" -ForegroundColor Cyan

# 步骤 1：检查已有 .venv
if (Test-Path "$VenvPath\python.exe") {
    $version = & "$VenvPath\python.exe" --version 2>&1
    Write-Host "[OK] .venv 已存在: $version" -ForegroundColor Green
} else {
    Write-Host "[INFO] 创建 .venv ..." -ForegroundColor Yellow

    # 步骤 2：从本地 ZIP 解压 Python
    if (-not (Test-Path $PythonZip)) {
        Write-Host "[ERROR] 未找到 $PythonZip" -ForegroundColor Red
        exit 1
    }
    Write-Host "[INFO] 解压 Python ZIP ..." -ForegroundColor Yellow
    Expand-Archive -Path $PythonZip -DestinationPath $VenvPath -Force

    # 步骤 3：引导 pip（ensurepip）
    Write-Host "[INFO] 引导 pip ..." -ForegroundColor Yellow
    & "$VenvPath\python.exe" -m ensurepip --upgrade
}

# 步骤 4：安装依赖（从公网 PyPI）
Write-Host "[INFO] 安装运行时依赖 ..." -ForegroundColor Yellow
& "$VenvPath\python.exe" -m pip install -r "$ProjectRoot\requirements-core.txt"
& "$VenvPath\python.exe" -m pip install -r "$ProjectRoot\requirements-db.txt"
& "$VenvPath\python.exe" -m pip install -r "$ProjectRoot\requirements-auth.txt"
& "$VenvPath\python.exe" -m pip install -r "$ProjectRoot\requirements-tts.txt"
& "$VenvPath\python.exe" -m pip install -r "$ProjectRoot\requirements-dev.txt"

# 步骤 5：初始化数据目录
New-Item -ItemType Directory -Force -Path "$ProjectRoot\data" | Out-Null

Write-Host ""
Write-Host "=== 环境初始化完成 ===" -ForegroundColor Green
Write-Host "Python: $VenvPath\python.exe"
Write-Host "启动后端: cd $ProjectRoot && .\.venv\python.exe -m horn --dev"
```

## 五、打包发布策略

### 5.1 三阶段构建流程

```
阶段一：开发环境初始化（setup.ps1）
  └─ 解压本地 Python ZIP → .venv/
     → ensurepip 引导 pip
     → 从公网 PyPI 安装所有依赖
     → 初始化数据目录

阶段二：产品构建发布（build_runtime.py）
  └─ 验证 .venv 存在
     → Phase 1: 智能构建 runtime/pythonenv/
        · 检测 python.exe + pip → 有效则跳过下载/解压
        · mtime 对比 requirements → 仅安装变更的依赖
        · 始终执行幂等清理（bloat packages, __pycache__, Scripts/）
     → Phase 2: 编译 horn 源码
        · 用 .venv 构建 wheel → 安装到 pythonenv
        · 编译 .py → .pyc (legacy) → 剥离 .py 源码
     → Phase 3 (可选): 深度 .pyc 编译
        · 编译 site-packages + stdlib 全部 .py → .pyc
        · 智能剥离 .py（仅删除有 .pyc 对应的文件）
     → Package: ZIP 打包
        · 复制 runtime/pythonenv/ + defaults/ + teacher-app/dist/
        · 生成 start-backend.bat + version.json + README.txt
        · 创建 ZIP + SHA256 校验
```

### 5.2 build_runtime.py 参数

```powershell
cd backend

# 基础构建（智能跳过已有环境）
python scripts/build_runtime.py

# 强制全量重建
python scripts/build_runtime.py --force

# 构建 + 深度 .pyc 编译
python scripts/build_runtime.py --phase2

# 构建 + 打包为 ZIP 发布包
python scripts/build_runtime.py --package

# 完整构建（强制 + 深度编译 + 打包）
python scripts/build_runtime.py --force --phase2 --package
```

### 5.3 Electron 打包（display-app）

使用 electron-builder，配置位于 `scripts/electron-builder.yml`：

```powershell
# display-app/scripts/build_electron.ps1

# 完整构建（前端 + NSIS 安装包）
.\scripts\build_electron.ps1

# 仅构建前端（不注入后端资源）
.\scripts\build_electron.ps1 -SkipBackend

# 清理后全量重建
.\scripts\build_electron.ps1 -Clean
```

> **注意**：大屏端为纯客户端应用，不再内嵌后端进程。构建产物仅包含前端静态资源和 Electron 壳。

**产物位置：**

```
display-app/release/Classroom-Horn-Portable-0.1.0.exe   # 便携版
```

### 8.2 环境准备过程中遇到的问题

#### 问题 1：pip --config-file 参数不支持
- **现象**：`no such option: --config-file`
- **原因**：Python 3.10.11 自带的 pip 23.0.1 版本较旧，不支持该参数
- **解决**：改用环境变量 `PIP_INDEX_URL` 和 `PIP_TRUSTED_HOST`

#### 问题 2：Path 未导入导致 NameError
- **现象**：`NameError: name 'Path' is not defined`
- **原因**：api.py 中使用了 `Path(__file__)` 但未导入 `pathlib.Path`
- **解决**：在文件顶部添加 `from pathlib import Path`
